# Outreach Templates

**What this is:** fill-in email/DM templates for listicle authors, conference organizers, podcasts, directories, and Hacker News.
**How to use it:** copy a template, replace every `[bracket]`, and personalize the opening line for the actual human you're writing to. Never send these verbatim in bulk.

---

## Honesty rules (read before sending anything)

1. **Personalize every send.** Reference the recipient's actual article, talk, or episode. If you can't name something specific they made, don't send.
2. **Disclose you're the maker.** Every pitch, post and comment says you're the founder of OneTime Suite. No astroturfing, no fake "happy user" accounts.
3. **One thread per community.** Don't carpet-post the same message across subreddits, forums, or Slack groups. Participate genuinely first; follow each community's self-promotion policy to the letter.
4. **Never buy links, reviews, or upvotes.** No link schemes, no paid listicle placements presented as editorial, no incentivized reviews.
5. **Real numbers only.** Every claim about price, features, or savings must match the README table and the competitor's live pricing page, with an "as of [date]" where relevant.

## (d) Directory submission checklist

| Directory | What it requires | Notes for OneTime Suite |
|---|---|---|
| **Product Hunt** | Product page: name, tagline (60 chars), description, gallery (images/GIF/video), first comment from maker, launch-day presence | Launch apps individually (BloomRecorder, Bookslot, WisperTalk first), not the whole suite at once. First comment must disclose you're the maker and explain the pay-once model. One launch per day max. |
| **AlternativeTo** | App listing: name, description, platforms, license/pricing model, link | List each flagship app as an alternative to its competitor (e.g. BloomRecorder as a Loom alternative). Pricing model: "One-time purchase". |
| **G2** | Verified business profile, product category, pricing info, screenshots; reviews must come from real users | Never incentivize or script reviews. Add `[N]` products only after real users exist who can review. |
| **Capterra** | Vendor account, product listing with pricing/deployment details | Same review rules as G2 (same network). Fill deployment accurately: self-hosted / desktop. |
| **SaaSHub** | Product listing + alternatives mapping | List each app against its README "Replaces" target. |
| **StackShare** | Tool profile; gets pulled into stacks | Most relevant for dev tools (Wrangle $15, Hookscope $69, Pingcron $79, Vaultkeeper $99). |
| **Indie Hackers** | Community account; product/milestone posts | Post milestones with real numbers only (apps shipped, sales count from `sales-data.js`). Participate in threads before posting your own. No drive-by links. |

Submission hygiene: same description accuracy everywhere (prices per README table), one account, real founder identity, update listings when prices change.

## (e) Hacker News "Show HN" template

HN rules that matter: submit one thing, be present in the comments, answer as the maker, don't ask anyone to upvote, don't post from sockpuppets, don't repost aggressively.

**Title options (plain, factual, no hype):**

- `Show HN: BloomRecorder – a Loom replacement you buy once ($29, 100% local, MIT MVP)`
- `Show HN: 102 pay-once apps replacing common SaaS subscriptions (65 shipped so far)`
- `Show HN: WhisperDesk – unlimited Whisper transcription on your own CPU ($39 once)`

**Body (for a text post or first comment):**

> Hi HN — I'm [Name]. I got tired of renting basic tools, so I'm building 102 pay-once apps that replace common subscriptions. Desktop apps run entirely on your machine (zero telemetry, zero accounts); web apps self-host on a $5 VPS.
>
> [For single-app posts:] Today's app: **[App name]** — [one-liner from README]. It replaces [competitor] ([competitor price] vs our $[price], once). The core is free and MIT-licensed here: [GitHub repo]. The paid version is the same app with polish, installers, and updates: [onetimesuite.com/<slug>/].
>
> Happy to answer anything — architecture, the 100-days build process, why [technical choice], or the economics of one-time pricing.

**Comment conduct:** reply to every substantive comment in the first hours; concede fair criticism; never argue about downvotes; if someone asks "why not just use [free alternative]?", answer honestly — including when the free alternative is the right choice.
